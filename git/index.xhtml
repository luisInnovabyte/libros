1. Esquema del flujo de trabajo de Git

🔄 Flujo de trabajo típico:

  1. Modificar archivos en el Working Directory
  2. Agregar cambios al Staging Area con git add
  3. Confirmar cambios al Local Repository con git commit
  4. Subir cambios a GitHub con git push

📝 Descripción de los espacios:

Espacio Descripción Estado de archivos
Working Directory Tu carpeta de trabajo donde modificas los archivos Modified, Untracked
Staging Area Área intermedia donde preparas los cambios para el commit Staged
Local Repository Base de datos local con el historial de commits Committed
GitHub (Remote) Servidor remoto donde se almacena y comparte el proyecto Pushed

2. Comandos básicos por espacio

🔧 Working Directory (Directorio de trabajo)

# Ver el estado de los archivos
git status

# Inicializar un nuevo repositorio
git init

# Configuración inicial obligatoria después de git init
git config --global user.name "nombre de usuario"
git config --global user.email "email usuario"

# Ver diferencias en archivos modificados
git diff

# Ver diferencias de un archivo específico
git diff archivo.txt

# Descartar cambios en el working directory
git checkout -- archivo.txt
git restore archivo.txt  # (versión más nueva)

📝 Staging Area (Área de preparación)

# Agregar archivos al staging area
git add archivo.txt                # Un archivo específico
git add .                          # Todos los archivos modificados
git add *.js                       # Todos los archivos .js
git add carpeta/                   # Toda una carpeta

# Ver archivos en staging area
git status                         # Estado general
git diff --cached                  # Diferencias de archivos staged

# Remover archivos del staging area
git reset archivo.txt              # Quitar un archivo específico
git reset                          # Quitar todos los archivos
git restore --staged archivo.txt   # (comando más nuevo)

💾 Local Repository (Repositorio local)

# Hacer commit de los cambios
git commit -m "Mensaje descriptivo del commit"

# Commit y add en un solo comando (solo archivos ya tracked)
git commit -am "Mensaje del commit"

# Ver historial de commits
git log                            # Historial completo
git log --oneline                  # Historial resumido
git log --graph                    # Con representación gráfica

# Ver diferencias entre commits
git show                           # Último commit
git show [hash-commit]             # Commit específico

# Deshacer commits
git reset --soft HEAD~1            # Mantiene cambios en staging
git reset --hard HEAD~1            # ⚠️ Elimina cambios completamente

🌐 GitHub/Remote Repository (Repositorio remoto)

# Conectar con repositorio remoto
git remote add origin https://github.com/usuario/repo.git

# Ver repositorios remotos
git remote -v

# Subir cambios al repositorio remoto
git push origin main               # Primera vez
git push                          # Subsiguientes pushes

# Descargar cambios del repositorio remoto
git pull                          # Fetch + merge
git fetch                         # Solo descargar sin mergear

# Clonar un repositorio
git clone https://github.com/usuario/repo.git

3. Configuración inicial de Git

# Configurar nombre y email (obligatorio)
git config --global user.name "Tu Nombre"
git config --global user.email "tu.email@ejemplo.com"

# Ver configuración actual
git config --list
git config user.name
git config user.email

# Configurar editor por defecto
git config --global core.editor "code --wait"  # Para VS Code
git config --global core.editor "nano"         # Para nano

# Configurar colores
git config --global color.ui auto

4. Trabajando con el Working Directory

# Estados de archivos en Git
# Untracked: Archivos nuevos que Git no rastrea
# Modified: Archivos rastreados que han sido modificados
# Staged: Archivos preparados para commit
# Committed: Archivos guardados en el repositorio

# Comandos útiles para working directory
git status -s                      # Status resumido
git diff HEAD                      # Diferencias con último commit
git checkout HEAD~1 archivo.txt    # Restaurar versión anterior

# Ignorar archivos
# Crear archivo .gitignore
*.log
node_modules/
.env
*.tmp

5. Gestión del Staging Area

# Agregar por partes (interactive)
git add -i                         # Modo interactivo
git add -p                         # Agregar por chunks

# Ver que hay en staging vs working directory
git diff                           # Working vs Staging
git diff --staged                  # Staging vs Repository

# Deshacer cambios en staging
git reset HEAD archivo.txt         # Quitar de staging
git restore --staged archivo.txt   # Comando más nuevo

6. Commits al Local Repository

# Buenas prácticas para commits
# - Usa mensajes descriptivos
# - Haz commits pequeños y frecuentes
# - Un commit por funcionalidad

# Tipos de commit
git commit -m "feat: agregar nueva funcionalidad"
git commit -m "fix: corregir bug en login"
git commit -m "docs: actualizar documentación"
git commit -m "style: mejorar formato del código"

# Modificar el último commit
git commit --amend -m "Nuevo mensaje"
git commit --amend                  # Abrir editor

# Ver información detallada de commits
git log --stat                     # Con estadísticas
git log --pretty=format:"%h - %an, %ar : %s"

7. Sincronización con GitHub

# Crear repositorio en GitHub y conectar
git remote add origin https://github.com/usuario/repositorio.git
git branch -M main                 # Renombrar rama a main
git push -u origin main            # Primera subida

# Workflow típico con GitHub
git pull                          # 1. Actualizar desde remoto
# 2. Hacer cambios locales
git add .                         # 3. Stagear cambios
git commit -m "mensaje"           # 4. Commit local
git push                          # 5. Subir a GitHub

# Gestión de remotos
git remote rename origin upstream  # Renombrar remoto
git remote remove upstream        # Eliminar remoto
git remote set-url origin nueva-url  # Cambiar URL

8. Ramas y merging

# Crear y gestionar ramas
git branch                        # Ver ramas
git branch nueva-rama             # Crear rama
git checkout nueva-rama           # Cambiar a rama
git checkout -b nueva-rama        # Crear y cambiar
git switch nueva-rama             # Comando más nuevo
git switch -c nueva-rama          # Crear y cambiar (nuevo)

# Mergear ramas
git checkout main                 # Cambiar a rama principal
git merge nueva-rama              # Mergear rama

# Eliminar ramas
git branch -d nueva-rama          # Eliminar rama (seguro)
git branch -D nueva-rama          # Forzar eliminación
git push origin --delete nueva-rama  # Eliminar rama remota

# Ver historial de ramas
git log --oneline --graph --all

9. Resolución de conflictos

# Cuando ocurre un conflicto durante merge
git status                        # Ver archivos en conflicto

# Los archivos en conflicto tendrán marcadores como:
# <<<<<<< HEAD
# Código de la rama actual
# =======
# Código de la otra rama
# >>>>>>> nombre-rama

# Después de resolver manualmente:
git add archivo-resuelto.txt      # Marcar como resuelto
git commit                        # Completar el merge

# Herramientas para resolver conflictos
git mergetool                     # Abrir herramienta gráfica
git config --global merge.tool vimdiff  # Configurar herramienta

# Cancelar merge en curso
git merge --abort                 # Volver al estado previo

10. Comandos avanzados

# Stashing (guardar cambios temporalmente)
git stash                         # Guardar cambios
git stash list                    # Ver stashes
git stash pop                     # Recuperar último stash
git stash apply stash@{0}         # Aplicar stash específico
git stash drop                    # Eliminar último stash

# Cherry-pick (aplicar commit específico)
git cherry-pick hash-commit       # Aplicar commit a rama actual

# Rebase (reescribir historial)
git rebase main                   # Rebase rama actual sobre main
git rebase -i HEAD~3              # Rebase interactivo

# Bisect (encontrar commit problemático)
git bisect start
git bisect bad                    # Marcar commit actual como malo
git bisect good hash-commit       # Marcar commit conocido bueno

# Tagging (etiquetas)
git tag                          # Ver tags
git tag v1.0.0                   # Crear tag ligero
git tag -a v1.0.0 -m "Version 1.0.0"  # Tag anotado
git push origin v1.0.0           # Subir tag
git push origin --tags           # Subir todos los tags

# Alias útiles
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.unstage 'reset HEAD --'
git config --global alias.visual '!gitk'

⚠️ Comandos peligrosos (usar con cuidado):

  • git reset --hard - Elimina cambios permanentemente
  • git push --force - Sobrescribe historial remoto
  • git rebase en ramas compartidas
  • git branch -D - Elimina rama sin confirmar merge
